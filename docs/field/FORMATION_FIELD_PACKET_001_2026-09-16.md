## 1. Purpose

This packet does **not** launch a retired-expert marketplace, student freelancing platform, generic AI consultancy, digital-transformation consultancy or staffing business.

It tests one narrower counterfactual exchange:

```text
ONE REAL CURRENT ACCEPTANCE-CRITICAL BLOCKER
+
CONTROLLER PERMISSION
+
BOUNDED DOMAIN JUDGMENT
+
BOUNDED AI / DIGITAL EXECUTION
+
EXPLICIT ACCEPTANCE EVIDENCE
+
ATTRIBUTABLE SETTLEMENT
→
CAN A TEMPORARY MICRO-CELL CREATE SURPLUS VS INTERNAL HANDLING?
```

The experiment is successful only if a real controller says yes with a real task, lawful boundaries and economics.

## 2. Why this test now

The Xuzhou SME digital-transformation pilot is now moving through assessment and acceptance rather than remaining a policy concept.

Current public truth includes:
- third-party acceptance awarded at RMB 2.197m;
- acceptance uses document review, on-site verification, personnel interviews and effectiveness determination;
- digital-level assessment packages are being awarded across the 650-enterprise trial;
- local first-batch service providers are implementing full-chain projects;
- the city already has consulting, expert and institutional support layers.

Therefore the field question is deliberately **not** “does digital transformation have demand?”

The field question is:

> Is there one small, current, acceptance-relevant capability gap that a primary controller does not want to solve with its permanent internal team, but would lawfully route to an externally composed, acceptance-bounded micro-cell?

## 4. Node roles — do not collapse them

### CONTROLLER
Primary service provider or pilot enterprise with task authority.

Owns:
- project truth;
- permission;
- necessary redacted inputs;
- acceptance authority or route to it;
- settlement commitment.

### DOMAIN_JUDGMENT
Authorized senior engineer, industry expert, qualified practitioner or other domain node.

Owns only the bounded judgment needed for the task:
- process constraints;
- failure modes;
- industrial reasonableness;
- domain review / QA.

`RETIRED` is not a required property. Age is not the resource; lawful callable judgment is.

### AI_EXECUTION
A qualified young/local AI/software executor or small technical node.

Owns bounded execution such as:
- data/evidence processing;
- automation;
- interface/integration glue;
- report/evidence generation;
- prototype or small workflow tool;
- implementation work explicitly permitted by the controller.

Being a student or young does not qualify the node. Evidence of capability is required.

### QA / ACCEPTANCE
The task packet must state who accepts and what evidence constitutes PASS.

### ORCHESTRATION
Founder/system owns:
- evidence contract;
- role separation;
- node optioning;
- permission boundaries;
- input/output interface;
- acceptance and rework boundary;
- attribution/economics;
- trust/risk governance;
- learning update.

Founder does not default to coding, consulting, data cleaning, ERP implementation or project administration.

## 7. After one packet exists — node optioning sequence

Do **not** recruit a generic expert pool or student pool first.

Sequence:

```text
LIVE BLOCKER
→ derive exact DOMAIN_JUDGMENT requirement
→ derive exact AI_EXECUTION requirement
→ search only those nodes
→ verify evidence/callability/permission
→ obtain conditional option
→ show exact composition to controller
→ controller approves roles + economics
→ only then execute
```

For DOMAIN_JUDGMENT, possible lawful search zones include:
- existing Xuzhou/Jiangsu expert mechanisms;
- university/research expert networks;
- qualified industry practitioners;
- retired/senior experts only where rights and current capability are clear.

For AI_EXECUTION, possible search zones include:
- local AI/software practitioners;
- OPC/startup-community participants;
- university technical teams;
- small specialist firms.

No node is selected because of age, unemployment, student status or enthusiasm alone.

## 9. PASS / FAIL

### PASS

```text
LIVE_BLOCKER
+
CONTROLLER_PERMISSION
+
DOMAIN_NODE_OPTIONED
+
AI_EXECUTION_NODE_OPTIONED
+
ACCEPTANCE_EVIDENCE_DEFINED
+
FEE_OR_SETTLEMENT_PATH
```

Then the experiment may move to `ECONOMIC_COMMITMENT` only after the controller explicitly accepts scope and economics.

### FAIL

Kill or downgrade if any of these are observed:
- provider handles the task internally at lower total cost;
- no shareable redacted blocker exists;
- external collaboration is disallowed;
- domain node adds no measurable value;
- execution node cannot meet industrial QA;
- acceptance is subjective/unbounded;
- fee attribution is impossible;
- coordination cost consumes the surplus;
- founder becomes the permanent worker;
- the model is indistinguishable from staffing/body-shopping/contact brokerage.
