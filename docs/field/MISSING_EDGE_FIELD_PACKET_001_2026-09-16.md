# Missing Edge Field Packet 001 — Non-OEM Maintenance Trace → Industrial AI

Date: 2026-09-16  
Status: `ORIGIN_TRUTH_BLOCKED / NO OUTREACH SENT`

## Why this packet exists

This is not a business plan and not a data-platform build request.

The first Formation-first cycle showed that complementarity alone is too weak. Before field promotion the route must survive:

`EXISTING EXCHANGE SEARCH -> OBSERVED STRUCTURAL FAILURE -> WHY NOT ALREADY SOLVED -> MISSING EDGE -> CHEAPEST DECISIVE VALIDATION`

The current candidate is:

`XZ-NONOEM-MAINTENANCE-TRACE-AI-001`

Hypothesis only:

> independent engineering-machinery service/rental actors may generate repair/failure traces that are operationally useful but not yet organized into a lawful, comparable, expert-adjudicated asset for industrial-AI training/evaluation.

This is **not yet proven**.

## Existing exchange structures already found

The route cannot claim novelty from any of the following:

- OEM/platform high-quality engineering-machinery datasets already exist;
- predictive-maintenance data products already exist;
- expert annotation and expert evaluation vendors already exist;
- high-quality dataset construction/evaluation platforms already exist;
- engineering-machinery OEMs are actively extending digital operations into aftermarket service.

Therefore the opportunity, if any, is **not** "industrial data", "expert annotation", "predictive maintenance", or "engineering machinery AI".

## Exact missing edge being tested

The narrow edge is:

`NON-OEM FIELD TRACE OWNER -> RIGHTS-CLEARED MINIMUM RECORD -> DOMAIN ADJUDICATION -> MODEL/EVALUATION BUYER`

The route survives only if existing OEM/platform routes do not already absorb this exact trace class at acceptable economics.

## Origin-side truth packet

Do not ask a service actor to send customer data, equipment serial numbers, photos, contracts, or actual maintenance records.

For each actor collect only the following first-pass metadata with permission:

- `ACTOR_TYPE`: independent repair shop / rental fleet / dealer / parts-and-service actor / other
- `RECORD_EXISTS`: yes/no
- `RECORD_MEDIUM`: paper / spreadsheet / ERP / service SaaS / chat / mostly oral
- `RECORD_FIELDS_ONLY`: blank field names or generic schema, no customer values
- `FAULT_DESCRIPTION_FIELD`: yes/no
- `SYMPTOM_FIELD`: yes/no
- `ROOT_CAUSE_FIELD`: yes/no/unknown
- `REPAIR_ACTION_FIELD`: yes/no
- `PART_REPLACEMENT_FIELD`: yes/no
- `OUTCOME_OR_REVISIT_FIELD`: yes/no
- `OPERATING_CONTEXT_FIELD`: yes/no
- `TECHNICIAN_NOTE_FIELD`: yes/no
- `HISTORY_LINKABLE_WITHOUT_IDENTITY`: yes/no/unknown
- `OWNER_OF_RECORD`: actor / OEM / customer / software provider / contract-defined / unknown
- `CONTRACTUAL_REUSE_ALLOWED`: yes/no/unknown
- `DEIDENTIFICATION_POSSIBLE`: yes/no/unknown
- `RETENTION_WINDOW`: rough category only
- `CURRENT_SECONDARY_USE`: none / training / analytics / OEM upload / insurance / other
- `WILLING_TO_DISCUSS_GOVERNED_PILOT`: yes/no, non-binding

## First pass threshold

Do not contact an AI buyer unless all of the following are observed:

1. at least 5 independent service/rental actors inspected;
2. at least 3 retain non-trivial maintenance/failure records;
3. at least 3 share a minimum common record class;
4. at least 2 have a plausible lawful path to authorize a de-identified derived artifact;
5. the records are not already obligatorily and comprehensively absorbed by an OEM/platform route.

Failure on 2-5 kills or materially narrows the candidate.

## Buyer-side truth packet

Only after the origin threshold passes, show an **abstracted schema only** to an industrial-AI / industrial-dataset buyer.

Ask:

- Does this field set contain information missing from your current datasets?
- Which fields would create incremental training/evaluation value?
- Is expert adjudication required? For which fields?
- What minimum sample volume would justify a pilot?
- What quality/consistency threshold is required?
- What rights documentation is mandatory?
- Would you pay for a bounded pilot if the origin rights and quality gates are satisfied?
- What would make the data worthless even if lawful?

No model build, platform build, data copying, annotation workforce build, or company registration before this answer.

## Promotion gate

`ORIGIN_RECORD_EXISTS`
+
`MINIMUM_COMMON_SCHEMA_EXISTS`
+
`RIGHTS_PATH_PLAUSIBLE`
+
`EXISTING_ROUTE_DOES_NOT_ALREADY_CLOSE_EDGE`
+
`BUYER_INCREMENTAL_VALUE_CONFIRMED`
+
`BOUNDED_PILOT_ECONOMICS`

Only then may the route progress from `MISSING_EDGE_HYPOTHESIS` toward field validation.

## Kill conditions

Kill immediately if:

- records are mostly oral or absent;
- customer/OEM/employer rights make derived reuse unavailable;
- the minimum common schema is too thin to preserve causal/diagnostic value;
- existing OEM/platform systems already collect the same traces under usable rights;
- buyers only value telemetry already available from OEMs;
- expert adjudication cost consumes the value;
- economics work only when the founder becomes the annotator, engineer, salesperson, or long-term project manager.

## Founder role

`FOUNDER = ORCHESTRATOR / PRINCIPAL / ROUTING CONTROL PLANE`

Founder defines evidence contracts, rights boundary, node roles, quality/acceptance and settlement. Founder is not the default repair technician, data-labeling worker, AI engineer, or sales runner.
