## Mission

Select one Xuzhou-grounded route in which value can be created by composing **heterogeneous nodes** rather than by turning the founder into the worker.

The scan is intentionally narrow. It compares only routes already supported by current public evidence and existing repository research.

The founder remains:

`ORCHESTRATOR / PRINCIPAL / ROUTING CONTROL PLANE`

The route should expose callable nodes such as demand streams, organizations, expert groups, instruments, supplier capacity, access channels, transaction rules and budgets.

- the listed demand is still live in the enterprise today;
- the stated budget is authorized or still available;

- the solution provider is willing and commercially available;
- IP / acceptance / settlement rules are sufficiently clear;
- a founder-controlled margin exists.

Therefore:

`DEMAND_STREAM_VISIBLE != ECONOMIC_COMMITMENT`

### Candidate A state

# Selected route

## `PUBLIC_TECH_DEMAND_STREAM → CAPABILITY / INSTITUTION ROUTING`

Candidate A is selected for the next P0 validation.

It is currently the strongest fit because:

1. the demand node already publishes concrete problems instead of requiring founder-led cold discovery;
2. the buyer organization is named;
3. economic intent is sometimes visible through intended R&D budgets or procurement values;
4. institutional routing / trust nodes already exist;
5. technical capability nodes can be searched nationally rather than personally performed by the founder;
6. solution submission / technology-transfer behavior is already structurally expected in this ecosystem;
7. the founder can remain in routing/governance while domain experts and institutions carry specialist work.

This is **not** a decision to become a technology-transfer consultant.

It is a test of whether an external orchestrator can legitimately compose:

```text
DEMAND STREAM
+
INSTITUTIONAL ACCESS
+
DOMAIN ANALYSIS
+
CAPABILITY SUPPLY
+
CONTRACT / ACCEPTANCE / SETTLEMENT RAILS
```

and retain an economically meaningful routing role.

# Next decisive external truth

The first external question should go to the **institutional routing node**, not to the enterprise and not to a professor.

We need to establish:

1. Are the public `进行中` demand records operationally current, or are some historical records still displayed as ongoing?
2. Can an independent individual / technology manager / external organization bring a candidate solution team for a listed need?
3. What is the legitimate participation path: public solution submission, technology-manager office, project cooperation, institutional introduction or another mechanism?
4. How are source attribution, commission / service fee / project-development compensation handled, if at all?
5. Who owns the enterprise relationship and who may contact the demand owner?
6. What minimum evidence is required before the institution will introduce a solution provider to an enterprise?
7. What are the IP, confidentiality and conflict-of-interest boundaries?
8. Can the same orchestrator repeatedly work across different listed needs rather than only one case?

## Promotion rule

Promote to `ROUTE_TESTABLE` only if the institution confirms a real participation path that preserves an explicit role for external demand/capability routing.

Promote further only after:

```text
ONE LIVE DEMAND CONFIRMED
→ ONE NON-FOUNDER DOMAIN ANALYST / CAPABILITY NODE OPTIONED
→ ONE LEGITIMATE INTRODUCTION OR SOLUTION SUBMISSION
→ ECONOMIC / ATTRIBUTION TERMS KNOWN
```

## Kill / demotion conditions

Demote this route if:
- public demands are materially stale and not maintained as real working inventory;
- only the institution itself may perform matching and no external routing role is recognized;
- there is no possible economic attribution to the external orchestrator;
- enterprise introductions are unavailable without founder becoming the specialist worker;
- solution providers can efficiently transact directly and the orchestrator adds no measurable surplus;
- the only monetization is selling founder hours.
