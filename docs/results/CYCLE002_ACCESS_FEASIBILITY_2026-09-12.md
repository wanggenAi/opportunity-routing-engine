# Cycle 002 — Operator Access Feasibility

Status: `CURRENT EXECUTION FEASIBILITY / NOT VALUE TRUTH`

## Core correction

A real latent-value structure can still be unusable for the current operator.

The project now separates:

```text
VALUE / EXCHANGE TRUTH
!=
CURRENT OPERATOR ACCESS / EXECUTION FEASIBILITY
```

The operator is itself an Actor. Its endowments matter:
- real professional history;
- accepted project/delivery contexts;
- technical and domain literacy;
- education/training;
- cross-context experience;
- communication/trust ability;
- local knowledge;
- warm paths / institutional roles;
- reputation references;
- resources that can be mobilized.

These can lower access friction in relevant contexts. They do not create entitlement to another actor's time, reputation, confidential knowledge or institutional resources.

Personal profile details are not persisted in this public repository by default. They belong in a runtime/private operator envelope when needed.

## Access hierarchy

Prefer:

```text
PUBLIC INSTITUTIONAL WINDOW
-> AUTHORIZED PROGRAM / EVENT
-> WARM REFERRAL
-> RECOGNIZED PROFESSIONAL ROLE
-> DIRECT COLD OUTREACH ONLY WITH A STRONG VALUE PACKET
```

The stronger / higher-trust the target actor, the more important role legitimacy and institutional cover become.

## Why counterpart attention must be earned

For every actor, answer:

```text
Why should this actor spend scarce time here?
What useful object does the operator bring before asking for help?
What does the actor gain if the hypothesis is correct?
What is the smallest reversible ask?
What status / face / reputation / confidentiality risk does the actor carry?
Who or what makes the interaction legitimate?
```

Compensation can be part of reciprocity, but it is not the only form. Depending on the actor, useful reciprocity may be:
- a funded project;
- a verified enterprise problem;
- a new commercialization route;
- research/field-validation data;
- institutional impact;
- recognition;
- training value;
- qualified demand;
- a serious bounded pilot;
- transparent professional fees.

## Architectural effect

Opportunity ranking must no longer ask only:

```text
Is the value real?
Can actors benefit?
Can someone pay?
```

It must also ask:

```text
Can the current operator legitimately enter this actor network?
Does the operator have relevant contextual credibility?
What is missing?
Can that gap be borrowed from an institution / partner / role?
What value packet earns the first interaction?
Is founder identity required forever, or does the route become institutional / repeatable?
```

A strong opportunity can remain `ACCESS_BLOCKED` and stay in the research pool.

The engine should prefer opportunities where:
- value is meaningful;
- access is realistically unlockable;
- credibility gaps can be bridged without deception;
- counterpart time/face/reputation cost is low relative to expected value;
- the initial ask is bounded;
- founder-specific access can later become a reusable organizational route.
