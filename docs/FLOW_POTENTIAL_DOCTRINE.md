# Flow Potential Doctrine — 势能差与被阻断的价值流

Status: `CANONICAL / LOCKED PRINCIPLE`

Constitutional parent: `docs/LATENT_VALUE_DOCTRINE.md`.

This document turns one core intuition into an operational rule for the repository:

> **A weak environment does not imply that value disappeared. It may mean that valuable actors, capabilities, resources, demand, capital and attention are present but are not flowing into exchange because the route between them is blocked.**

The engine therefore does not merely search for "opportunities". It searches for **evidenced potential differences** and the blockers that prevent value from flowing across them.

`势能差 / FLOW_POTENTIAL` is an analytical metaphor, not a physical quantity and not a license to invent numeric precision.

## 1. The object is blocked flow, not idle resource alone

Underuse is important, but underuse alone is not a business.

```text
IDLE / UNDERUSED RESOURCE
!=
COMMERCIAL OPPORTUNITY
```

A commercially serious route requires evidence for all of the following:

```text
EVIDENCED UNDERUSED / MISALLOCATED CAPABILITY OR RESOURCE
+
EVIDENCED VALUED OUTCOME / PAYING DEMAND
+
EVIDENCED TRANSACTION FRICTION
+
A BRIDGEABLE ROUTE
→
FLOW-POTENTIAL HYPOTHESIS
```

Promotion remains fail-closed:

```text
UNDERUSE != DEMAND
NEED != PAYING DEMAND
BENEFICIARY != PAYER
COMPLEMENTARITY != ROUTE
ROUTE != TRANSACTION
INTEREST != COMMITMENT
COMMITMENT != SETTLEMENT
```

The system may observe a large social waste and still conclude `NO EXECUTABLE ROUTE`.

## 2. Actor dignity is architectural, not rhetorical

A person is an `ACTOR`, not a resource inventory item.

The person's bounded, voluntarily offered and verifiable capabilities may become routable resources:

```text
PERSON = ACTOR
TIME / SKILL / KNOWLEDGE / EXPERIENCE / TRUST / ACCESS = POSSIBLE CAPABILITY OR RESOURCE
```

The engine must not optimize for "how to use idle people" as if people were inert stock.

It should ask:
- what the actor can actually do;
- what the actor wants or refuses;
- what constraints the actor has;
- what outcome the actor can credibly produce;
- under what terms the actor voluntarily participates;
- how value and risk are distributed;
- whether compensation is fair and transparent.

Human-capital activation is successful only when capability becomes **more legible, more usable and more valuable to the actor as well as to the payer**.

## 3. Canonical potential-difference dimensions

The engine should be able to observe potential differences across multiple dimensions without assuming a permanent industry taxonomy.

### `CAPABILITY / CAPACITY POTENTIAL`
Useful capability exists in excess, fragmented or mistimed form while another actor pays for the outcome elsewhere.

### `INFORMATION POTENTIAL`
Decision-grade information exists or can be produced, but one actor cannot cheaply obtain, verify or interpret it.

### `TRUST POTENTIAL`
Complementary actors exist, but identity, quality, liability, acceptance or recourse prevents exchange.

### `TIME POTENTIAL`
Capacity and demand exist at different times; timing mismatch creates cost, delay or lost revenue.

### `SPACE / GEOGRAPHY POTENTIAL`
A capability, asset, relationship or observation is local while the valued outcome is elsewhere.

### `PRICE / COST-STRUCTURE POTENTIAL`
The outcome is valued, but the incumbent transaction form makes it too expensive; decomposition, aggregation, technology or a different contract may change the economics.

### `COORDINATION POTENTIAL`
All required pieces exist, but assembling them has a transaction cost high enough to justify orchestration.

### `AUTHORITY / ACCESS POTENTIAL`
The actors or resources exist, but permission, backing, contract rights, institutional access or a trusted introduction is missing.

### `AGGREGATION POTENTIAL`
Individual fragments are uneconomic while aggregated demand, supply, evidence or acceptance becomes transaction-worthy.

These are observation lenses. They must not become fixed assumptions about what reality is allowed to contain.

## 4. The canonical blocked-flow chain

```text
OBSERVATION
→ ACTOR / STATE / CHANGE
→ CAPABILITY / RESOURCE / VALUED OUTCOME
→ FRICTION / BLOCKER
→ FLOW-POTENTIAL HYPOTHESIS
→ COMPLEMENTARY ACTOR / ROUTE HYPOTHESIS
→ CHEAPEST DECISIVE VALIDATION
→ REAL COMMITMENT
→ EXECUTION
→ ACCEPTED OUTCOME
→ SETTLEMENT
→ VALUE FLOW
→ REPEAT / LEARNING
```

The engine's job is not complete at candidate generation.

A candidate that never advances toward validation or transaction is research inventory, not realized value.

## 5. The orchestrator is a flow enabler

The durable role of the orchestrator is to reduce a real blocker, for example by:
- making hidden capability legible;
- converting vague work into an accepted CapabilityUnit;
- making a payer and acceptance rule explicit;
- aggregating fragments;
- reducing search cost;
- creating a trust or evidence layer;
- aligning time or geography;
- composing backing and access;
- coordinating multiple actors;
- changing the transaction structure;
- capturing outcome evidence so the next transaction is cheaper and safer.

The orchestrator should earn only where it creates incremental value.

```text
MERE INTRODUCTION != DURABLE ORCHESTRATION VALUE
CONTROL OF INFORMATION != VALUE BY ITSELF
WEAKER ACTOR'S DESPERATION != LEGITIMATE MARGIN
```

## 6. Bad environments are hypotheses, not conclusions

Statements such as "the environment is bad", "there are too many graduates", "capital is not investing" or "consumption is weak" are macro observations at most.

They may imply increased probability of:
- idle human capability;
- unused equipment or space;
- inventory pressure;
- fragmented demand;
- lower willingness to make large commitments;
- preference for variable-cost / pay-per-result structures;
- risk aversion and trust friction;
- capital seeking lower-risk or clearer-return routes.

But the engine must descend from macro narrative to transaction evidence.

```text
MACRO PRESSURE
→ OBSERVABLE ACTOR CHANGE
→ OBSERVABLE UNDERUSE / DEFICIT
→ OBSERVABLE FRICTION
→ TESTABLE ROUTE
```

If that chain cannot be evidenced, the macro story does not pass.

## 7. Discovery without execution is an incomplete loop

The repository is allowed to improve its sensors, ontology and evidence model only while those improvements reduce a real discovery or validation bottleneck.

Once the system can produce a bounded route with sufficient evidence, the priority changes from architecture to reality.

The next truth must come from an external actor, not another internal abstraction.

This creates a structural stop condition against endless optimization:

```text
IF A REAL ROUTE CAN BE TESTED CHEAPLY
THEN FIELD VALIDATION OUTRANKS GENERAL ARCHITECTURE IMPROVEMENT
```

A new sensor, ontology layer, workflow or scoring dimension is not P0 merely because it makes the system more complete.

It becomes P0 only when it materially unblocks an active route, closes a truth gap that blocks a decision, fixes production reliability, or converts repeated manual work into reusable system capability.

## 8. First-value-flow proof

The smallest decisive proof of this doctrine is not a large platform, market size estimate or perfect world model.

It is one externally evidenced loop:

```text
REAL ACTOR
→ REAL VALUED OUTCOME
→ REAL PAYER / ECONOMIC COMMITMENT
→ REAL CAPABILITY / RESOURCE
→ REAL BLOCKER REDUCED
→ REAL DELIVERY
→ REAL ACCEPTANCE
→ REAL SETTLEMENT
```

The first proof may be small in money.

Its importance is epistemic: it demonstrates that the engine can move from sensing a potential difference to causing value to flow.

## 9. Governing sentence

> **观其势，不执其名；见有余与不足，不把人本身物化为资源，而看见 Actor 身上可自愿调用的能力、时间、知识、信用与关系。寻找这些价值与真实付费结果之间的势能差，证明是什么阻住了流动；若阻塞可被低成本、合规、透明地解除，就以软件、信息、信任、组织和规则疏通它，让原本闲置或错配的价值进入真实交换。不能形成真实承诺、验收与结算的，只能是待证假设。**
