## Scan-level learning

CALLABLE ACTION GATE IS NECESSARY, BUT CALLABLE DOES NOT MEAN STANDARDIZED ACROSS THE CATEGORY.

CASE-BY-CASE PERMISSION != TRANSACTION RAIL
VISIBLE MATCH + MANUAL APPROVAL != HIGH ATTRACTION
NATIVE TRANSACTIONABILITY > PERMISSION ARCHAEOLOGY

The new hard-floor question is: once A and B are matched, can the same economic action be invoked again and again under stable, enumerable rules?

Score guidance:
0 = no lawful/usable action rail observed
1 = fragmented / case-by-case / incumbent-discretionary permission
2 = stable repeatable rules with self-service or standard onboarding
3 = native API / transaction / booking / transfer / settlement rail

## Strong anti-pattern exposed

A and B visible -> match looks obvious -> contact organizer/platform/provider to ask whether this transaction is allowed.

That is not a narrow bridge. The operator is still dependent on permission discovery.
