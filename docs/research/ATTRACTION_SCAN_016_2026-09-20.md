## F1 — 9610 cross-customs return router

### Structural change

China Customs Announcement No. 24 of 2026 made a previously constrained routing
decision materially more movable.

From 2026-04-01, 9610 cross-border e-commerce retail exports returned from overseas no
longer have to return through the original export customs district. They may return
through another customs district, but only to customs-supervised operational sites that
conduct cross-border e-commerce retail export business.

Official/current sources:
- https://search.customs.gov.cn/eportal/ui?pageId=c831ad4a8c214922931777e86c67f9eb
- https://policy.mofcom.gov.cn/claw/policyInfo.shtml?id=8849
- https://commerce.sz.gov.cn/xxgk/qt/swzx/content/post_12689998.html

The Shenzhen Commerce Bureau reports that by the end of February 2026 the earlier
pilot had already handled 381,300 cross-district return shipments with RMB 94 million
of goods value.

This is not merely a new article or a new advisory rule. It changes the feasible action
set:

```text
BEFORE
RETURNED 9610 GOODS
→ ORIGINAL EXPORT CUSTOMS DISTRICT

NOW
RETURNED 9610 GOODS
→ CHOOSE AMONG ELIGIBLE CUSTOMS-SUPERVISED RETURN SITES
```

That creates a new routing question.

### User-side economic object

The seller does not merely need "a return warehouse".

The actual decision is closer to:

```text
OVERSEAS RETURN EVENT
+
CURRENT COUNTRY / CARRIER / WAREHOUSE
+
SKU / WEIGHT / DIMENSIONS / GOODS ATTRIBUTES
+
9610 RETURN ELIGIBILITY
+
ELIGIBLE CHINA RETURN SITE
+
REVERSE FREIGHT
+
CUSTOMS / HANDLING / WAREHOUSE COST
+
EXPECTED CLEARANCE + INBOUND TIME
+
RESELL / RESTOCK VALUE WINDOW
↓
WHICH LEGAL RETURN ROUTE
MAXIMIZES EXPECTED RECOVERED VALUE?
```

The policy explicitly permits route choice because logistics cost and time can differ.
That makes "which return port/site/rail?" a real decision rather than a hypothetical
optimization.

### Machine-callable execution evidence

Current overseas-warehouse systems already expose machine-callable reverse operations.

GoodCang current open API material exposes:
- return warehouse code;
- return inspection vs destruction service;
- courier / tracking;
- sellable, unsellable and destruction quantities;
- return photos;
- return status;
- fee details;
- warehouse and collection-warehouse information.

Source:
- https://oms.goodcang.com/default/open/api-call

Other current cross-border WMS/warehouse systems expose similar return-order,
inspection, relabel, inventory and reverse-logistics flows. This proves that the
physical reverse process can be represented as machine state rather than requiring the
router itself to inspect every parcel.

Important boundary:

`OVERSEAS_RETURN_API_EXISTS != TWO_PROVEN_9610_CROSS-CUSTOMS_RETURN_RAILS`.

The exact China re-entry / customs-supervised-site action must still be verified on at

## Scan learning

```text
POLICY REMOVES A PREVIOUSLY FIXED ROUTE
+
MULTIPLE EXECUTION SITES BECOME LEGALLY CHOOSABLE
+
THE DECISION WINDOW IS LIVE
+
REAL EXECUTION RETURNS COST/TIME/ACCEPTANCE OUTCOMES
→ POSSIBLE TEMPORARY ROUTING EDGE
```

This class deserves future broad-reality attention.

But:

```text
NEW POLICY != BUSINESS
MORE CHOICES != ROUTER
API != MULTI-RAIL CALLABILITY
SERVICE PROVIDERS != OPERATOR ECONOMICS
```
