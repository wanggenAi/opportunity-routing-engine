## Direction 1 — Used-car realized-sale routing

The economic pattern is real:

```text
DISPLAYED VALUATION / INITIAL OFFER
!=
FINAL TRANSACTION VALUE
```

But the obvious cross-platform route is already occupied.

Che300 already markets multi-platform used-car price comparison and one-click sale
distribution. Its data business also aggregates large dynamic market datasets and
valuation signals. Used-car auction platforms add standardized inspection and dealer
bidding.

Representative sources:
- https://www.che300.com/
- https://cloud.che300.com/
- https://www.ttpai.cn/

Verdict:
`DEMOTED / CROSS_PLATFORM_VALUATION_AND_DISTRIBUTION_ALREADY_OCCUPIED`.

A new router would need a materially different cross-platform realized-sale asset, not
another valuation or listing layer.

## Direction 2 — Gold / jewelry realized-payout routing

This was a serious near miss.

Gold recycling has a machine-legible hidden outcome:
- posted / reference gold price;
- submitted item;
- inspection;
- measured weight / purity;
- deductions;
- final payout;
- payment completion.

China's current digital rails prove that gold recycling is not purely offline:
Alibaba/Xianyu open-platform surfaces include gold-recycling service-provider pricing,
recycling quotation, inspection-report, order-state and payment-state interfaces.

Representative sources:
- https://open.taobao.com/
- https://open.goofish.com/
- https://www.gold.org.cn/

Positive:
```text
QUOTE → INSPECTION → FINAL PAYMENT
CAN BE MACHINE-SHAPED
```

Kill:
Xianyu itself is the service-provider aggregation/control layer. It can naturally
observe the cross-provider quotes, inspection reports, order outcomes and payment
outcomes inside its own marketplace. Outside that control plane, current search did not
establish a second equally open, independent gold-recycling transaction rail.

Therefore:

```text
ONE STRONG AGGREGATE RAIL
+
OTHER DIRECT / MANUAL CONSUMER RAILS
!=
MULTIPLE INDEPENDENT CALLABLE RAILS
```

Verdict:
`DEMOTED / SUPER_AGGREGATOR_OWNS_INTERNAL_CROSS_PROVIDER_OUTCOME_HISTORY`.

## Cross-direction learning

Scan 019 kills another attractive but insufficient pattern:

```text
MULTIPLE APIS
+
NATIVE COMMISSION
+
POST-EXECUTION OUTCOME
!=
DISTINCT ROUTING ASSET
```

Two common failure modes dominate:

### Failure A — super-aggregator ownership

```text
MULTIPLE SUPPLIERS
→ ONE EXISTING AGGREGATOR
→ AGGREGATOR SEES ORDERS + OUTCOMES
→ ROUTER HAS NO UNIQUE CROSS-RAIL HISTORY
```

### Failure B — decisive outcome does not naturally flow back

```text
MULTIPLE CALLABLE RAILS
+
REAL USER EXPERIENCE DIFFERENCE
BUT
THE DECISIVE EXPERIENCE EXISTS ONLY ON THE USER'S DEVICE / PRIVATE SYSTEM
→ EXTRA TELEMETRY / APP / ACTIVE TEST REQUIRED
→ SELF-PROPULSION WEAKENS
```

Travel eSIM is the cleanest current example of Failure B.

## Scan-020 boundary

The next search should test whether Failure B can become an advantage.

Prefer a structure where:

1. the decisive realized outcome is naturally observable in the user's existing device
   or business system;
2. observation can be passive / automatic after permission, not repeated manual input;
3. multiple paid execution rails are already callable;
4. switching or reordering is frequent enough that the outcome changes the next action;
5. no individual rail and no existing super-aggregator naturally owns the normalized
   cross-rail realization signal;
6. operator economics attach to the routed transaction;
7. the telemetry is materially more decision-useful than public reviews.

Compact form:

```text
USER-OWNED PASSIVE REALIZATION TELEMETRY
+
MULTIPLE PAID CALLABLE RAILS
+
LOW-FRICTION REPEAT / SWITCH
+
TRANSACTION-LINKED ECONOMICS
+
NO SUPER-AGGREGATOR OWNS THE JOIN
→ POSSIBLE SELF-COMPOUNDING ROUTING ASSET
```

This is a structural boundary, not an eSIM prior.
