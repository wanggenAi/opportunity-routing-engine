## F1 — Cross-system internal marketing operations

A July 2026 participant described an internal marketing system that had been delayed for almost four years because business knowledge repeatedly crossed product, engineering and testing handoffs. By directly decomposing the rules with AI, the participant connected three internal systems and reached a runnable trial in roughly five focused development days. Sensitive actions remain dry-run-first and human-approved.

Source:
- https://v2ex.com/t/1226578

This is strong evidence that participant-owned APIs and operational state can support reliable machine execution. It is not evidence of a durable external operator edge. Current automation platforms already expose custom APIs, code, triggers, branching, human approvals, error handling and run tracing:

- https://n8n.io/
- https://www.dify.ai/workflows

The remaining difficulty is local API semantics, fragmented business rules, permissions and ongoing change. That is valuable internal engineering, but without an independently evidenced reusable control asset it defaults toward bespoke integration.

**Verdict:** demoted.

## F2 — Team SMS/OTP routing

A March 2026 participant described a team operating many official-account, Zhihu and ecommerce identities through old Android phones plus SmsForwarder. Missed messages, crashes and credential-control risk led to a dedicated Cat.1 gateway plus cloud routing layer. The author publicly quoted a 199 CNY device buyout and a 99 CNY/month or 998 CNY/year team plan.

Source:
- https://www.v2ex.com/t/1199028

The formation therefore contains real observed pain, an implemented state transition and a live monetization attempt. But exact incumbent pressure is decisive. SmsForwarder already provides rules-based SMS/notification forwarding to DingTalk, WeCom, Feishu, email, webhook and other channels:

- https://github.com/pppscn/SmsForwarder

The observed participant's own gateway-plus-SaaS is also already an exact active route. The remaining reliability boundary depends on device/SIM availability, carrier delivery and external identity-provider MFA policy.

**Verdict:** demoted.

## F3 — Agent worktree local asset synchronization

A September 21, 2026 participant using Codex with parallel git worktrees reported that company policy prevents committing `.agents`, leaving project research, issue documents and skills absent in newly created worktrees. The participant also wants untracked updates to flow back and conflicts to be handled when multiple worktrees modify the same local asset.

Source:
- https://v2ex.com/t/1243449

This is nearly ideal action-rights evidence because the files and worktree operations are fully local and participant-controlled. It also demonstrates the trap. Worktrunk already exposes `wt step copy-ignored`, lifecycle hooks and `.worktreeinclude` for controlled copying between worktrees:

- https://worktrunk.dev/step/
- https://github.com/max-sixty/worktrunk/blob/main/.worktreeinclude

A short hook, symlink or shared directory can also solve the propagation layer. If multiple untracked copies must be independently edited and later merged, the missing object is an authoritative history/conflict policy — not another generic copy service.

**Verdict:** demoted.

## Cross-pass learning

Scans 097 and 098 now provide two independent participant-controlled digital-action-rights passes.

The repeated pattern is:

```text
PARTICIPANT OWNS CREDENTIALS / LOCAL STATE
+ ACTION IS HIGHLY MACHINE EXECUTABLE
→ DELIVERY FEASIBILITY IMPROVES
BUT
THE SAME RIGHTS ARE AVAILABLE TO GENERIC AGENTS / OPEN SOURCE / WORKFLOW PLATFORMS
→ OPERATOR EXCLUSIVITY AND NORMALIZED MARGIN COLLAPSE
```

The second pass is enough to change the evidence priority without inventing a product. Scan 099 should no longer lead with participant-controlled digital action rights alone. It should require current China evidence of a **reusable operator control advantage** — a control surface, execution right, data advantage or routing asset that materially improves the outcome beyond what participant credentials, generic agents, active open-source tools and mature workflow platforms can already do.

This is an evidence filter, not a prescribed business model.
