## Direction 1 — legacy industrial automation spare substitution

Observed evidence:

- KEYENCE publishes discontinued PLC/HMI models together with recommended replacement models and repair cutoffs.
  - https://www.keyence.com.cn/support/user/controls/discontinued/repair/
- Schneider Electric exposes product selection and product substitution tooling.
  - https://www.se.com/ww/en/work/support/country-selector/substitution-tool/
- Cross-brand industrial suppliers explicitly sell stopped-model sourcing and cross-brand substitution, but ask for model, nameplate/photo and application context and perform replacement-direction evaluation.
  - https://www.furuya.cn/nonstandard.html

Attraction:

- downtime-linked value can be large;
- 1688/distributor rails can execute procurement;
- a cross-brand compatibility graph would be more specialized than ordinary prompt reasoning.

Kill:

```text
THE HARD PART IS PRECISE APPLICATION-SPECIFIC SUBSTITUTION
→ OEMS OWN BRAND-NATIVE SUBSTITUTION
AND
CROSS-BRAND CASES STILL REQUIRE RECURRING ENGINEERING JUDGMENT
→ EXPERT_MATCHING_REQUIRED_PER_TRANSACTION
→ LOW_ATTRACTION
```

A narrower standardized subcategory would become more machine-resolvable, but then the information collapses toward public catalog/parameter matching and loses distinctiveness.

Verdict: `EXPERT_DEPENDENT_OR_INCUMBENT_PARTIAL_GRAPH`.

## Cross-direction structural result

Scan 014 exposes a three-way trap:

```text
1. PUBLIC + STRUCTURED SPECIALIZED GRAPH
   → GENERIC / PLATFORM / DATA-INCUMBENT COMMODITIZATION

2. NON-PUBLIC APPLICATION-SPECIFIC DECISION
   → RECURRING EXPERT JUDGMENT

3. OUTCOME-DERIVED DISTINCT ASSET
   → STRONGEST MOAT CANDIDATE,
     BUT ONLY IF THE ROUTED TRANSACTION ITSELF GENERATES THE OUTCOME DATA
     AND THE RAIL OWNER DOES NOT ALREADY OWN IT
```

This changes the next search boundary.

The next attractive asset should not be a public parameter graph that we merely compile more neatly. It should be an **acceptance / rejection / success / failure graph generated as a side effect of real routed transactions**, so each execution improves the next machine decision.

- the operator must repeatedly hunt users/providers or manually deliver the result.
