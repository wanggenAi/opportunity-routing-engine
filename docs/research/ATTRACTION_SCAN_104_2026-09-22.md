## Purpose

Scan 103 proved that real non-commodity control plus real money can still be useless to a fresh operator when the scarce asset is incumbent-owned history, identity, audience, contract status or ranking.

Scan 104 repeats the same evidence floor independently, but makes one question explicit:

```text
CAN A FRESH INDEPENDENT SMALL OPERATOR
LEGALLY OBTAIN / BUILD / CONTRACT / ASSEMBLE
THE DECISIVE NON-COMMODITY POSITION
WITHOUT ALREADY OWNING THE INCUMBENT'S HISTORY?
```

The scan does not start from apps, plugins, games or asset markets. Those are only the formations that survived broad sensing far enough to test the control-change boundary.

## F1 — Profitable app with installed user base offered for transfer

A China developer posted on 2026-02-24 that a three-month-built app supporting iOS, APK and web had nearly 20,000 users, about 1,500 DAU, roughly 500 new users per day, about 10,000 iOS downloads in the prior month and had already become profitable. The developer explicitly wanted to sell because a work change made continuing development impractical.

Participant source:
- https://global.v2ex.com/t/1193821

Apple's current App Store Connect documentation is important because it proves that the control change itself is not hypothetical. Apple explicitly supports transferring ownership when an app is sold to another developer. The app can remain downloadable, retains reviews and ratings, keeps its Bundle ID and continues to receive updates.

Objective sources:
- https://developer.apple.com/help/app-store-connect/transfer-an-app/overview-of-app-transfer
- https://developer.apple.com/help/app-store-connect/transfer-an-app/app-transfer-criteria

This is the strongest fresh-entry shape in the pass. Unlike Scan 103's repository/audience/SEO history, some path-dependent distribution state can actually move to a new owner.

It still fails closed. The exact app is withheld, so none of the user, DAU, download, review, ranking or profit claims can be independently tied to a visible product. Revenue amount, retention, costs, asking price, code quality, domain/server transfer and lawful user-data transfer across iOS/Android/web are also unknown.

**Verdict:** demoted, but the transfer-continuity distinction is retained as a learning.

## F2 — UCharts public Figma distribution to direct sales

The UCharts operator reported USD 259 of Figma-plugin revenue for July 2026. Earlier public posts identify the exact UCharts plugin and the current Gumroad page identifies the Figma Plugin / Widget / Web App bundle and shows direct sales.

Participant / product sources:
- https://edge.v2ex.com/t/1231403
- https://edge.v2ex.com/t/1188003
- https://cn.v2ex.com/t/1164546
- https://tangweikun.gumroad.com/l/ucharts

Figma's current creator documentation closes the decisive entry question: ownership of plugins published outside an organization cannot be transferred. Figma gives published plugins a persistent Community listing, but the existing public listing/distribution history cannot simply be bought and moved to an unrelated fresh operator.

Objective source:
- https://help.figma.com/hc/en-us/articles/360042293714-Manage-classic-plugins-as-a-developer

So the current operator has real money plus a path-dependent distribution asset, but the asset is **non-transferable precisely at the platform control surface**. Buying source code would not buy the same Community identity/history.

**Verdict:** demoted.

## F3 — One-person game IP to publisher-operated minigame revenue

Unity China's publishing case for `幻境深渊` is a materially different control shape. The game was developed by one person. The developer gave the game to the publisher, passed evaluation and signed a contract; Unity China's publishing side reports that it then handled minigame conversion, technical optimization, listing, filing, commercial tuning, ad creative production and data optimization. The case reports a peak monthly turnover above RMB 300,000 and later monthly turnover in the high tens of thousands to roughly RMB 100,000.

Publishing case:
- https://unity.csdn.net/685633777e10b149bf209dea.html

The exact game remains visible and was updated in 2026 on Google Play:
- https://play.google.com/store/apps/details?hl=zh&id=com.pujiagames.FantasyJourney

Current Unity China ecosystem material still advertises publishing/channel support for developers:
- https://unity.cn/ucdc2026

Current Douyin minigame qualification rules independently confirm that software-copyright operating/publishing authorization and third-party IP authorization chains are valid current mechanisms when the rights owner and operating entity differ:
- https://partner.open-douyin.com/docs/resource/zh-CN/mini-game/operation1/norms/credential-norms-for-mini-game

This proves that non-commodity IP plus contractible downstream operating rights can produce founder-light execution. But it does **not** expose a new routing layer for us. The publisher already owns the conversion/compliance/distribution/commercialization bridge. A fresh operator still needs to create or acquire a game good enough to win publisher acceptance, while the exact revenue share, user-acquisition spend and net margin are undisclosed.

**Verdict:** demoted.

## Learning

Two independent non-commodity-control passes now distinguish three different states:

```text
SCARCE BUT INCUMBENT-LOCKED
  -> Scan 103 dominant case

SCARCE AND TECHNICALLY TRANSFERABLE
  -> Scan 104 F1, but economics / full rights unverified

SCARCE AND REVENUE-BEARING BUT PLATFORM-NONTRANSFERABLE
  -> Scan 104 F2

CONTRACTIBLE IP + OUTSOURCED OPERATIONS
  -> Scan 104 F3, but mature publisher owns orchestration
```

The next useful evidence jump is therefore not another scarcity label. It is:

```text
ACTUAL CONTROL CHANGE
+ FRESH OPERATOR RECEIVES THE DECISIVE POSITION
+ EXTERNAL MONEY CONTINUES AFTER TRANSFER
+ ORIGINAL FOUNDER IS NOT STILL THE RECURRING DELIVERY ENGINE
+ NORMALIZED ECONOMICS / RIGHTS ARE BUYER-VERIFIABLE
```

Scan 105 should search for that property across fresh, formation-diverse current reality. It must not become an app-acquisition, plugin-acquisition, game-acquisition or marketplace-feed ontology.
