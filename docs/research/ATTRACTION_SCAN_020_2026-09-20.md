## Direction 1 — Residential / scraping proxy routing

This is almost the canonical passive-telemetry case:

- every request exposes success/failure;
- latency is automatically measurable;
- blocking is observable;
- providers are API-callable;
- switching can happen request by request;
- price is machine-readable.

But the exact independent control layer already exists.

ScrapeOps currently aggregates 20+ proxy providers behind one endpoint, continuously
monitors provider performance, automatically switches providers when one degrades or is
blocked, and optimizes by performance and price.

Sources:
- https://scrapeops.io/proxy-aggregator/
- https://scrapeops.io/docs/proxy-aggregator/overview/

Verdict:
`DEMOTED / EXACT_PASSIVE_OUTCOME_ROUTER_ALREADY_EXISTS`.

## Direction 2 — Multi-CDN real-user-performance routing

Again, the mechanism is nearly perfect:

```text
REAL USER LATENCY / AVAILABILITY
→ PASSIVE RUM
→ SWITCH CDN
→ OBSERVE NEXT USER OUTCOME
```

IBM NS1 Connect / Pulsar already does this explicitly. It collects real-user monitoring
data, compares multiple CDNs and cloud regions, and routes users dynamically by
performance, availability and cost.

Source:
- https://www.ibm.com/products/ns1-connect/multi-cdn
- https://www.ibm.com/docs/en/ns1-connect?topic=pulsar-traffic-steering-rum

Verdict:
`DEMOTED / RUM_TO_MULTI_CDN_ROUTING_IS_MATURE_INFRASTRUCTURE`.

## Direction 4 — Coding-agent / model execution routing

This is even closer to the desired outcome asset because the user's own repository can
produce an objective verifier:

```text

→ AGENT / MODEL
→ CODE CHANGE
→ TEST / BUILD RESULT
```

The 2026 Agent-as-a-Router work formalizes a Context → Action → Feedback → Context loop,

Sources:

Verdict:
`DEMOTED / EXECUTION_GROUNDED_AGENT_ROUTING_IS_ALREADY_AN_ACTIVE_CONTROL_SURFACE`.

## What remains locked

The mechanism reset does **not** weaken business quality.

Continue to require:
- visible voluntary energy;
- discoverable/addressable actors or events;
- a narrow enough value bridge to execute;
- no permanent founder cold-sales engine;
- no permanent founder professional delivery;
- legal / rights feasibility;
- real willingness to pay or transaction economics before promotion;
- reusable learning, data, trust, distribution, rights, workflow position or other
  compounding operator advantage;
- truthful fail-closed evidence.

But do **not** require every new formation to have:
- multiple providers;
- a cross-rail graph;
- passive telemetry;
- an API router;
- a commission;
- an acceptance/rejection graph.

Those are mechanisms, not constitutional truths.
