## Cross-direction structural finding

The decisive correction is:

```text
PRIVATE CONTEXT
+
LIVE EXTERNAL RESOURCE
!=
UNOWNED ROUTING EDGE
```

Stable private state is attractive to incumbents. Once a market is valuable, the
external platform can:
- add ERP/MES/LIMS integrations;
- ingest inventory/telemetry/work-order state;
- build internal APIs;
- absorb the join.

Therefore the private state must not merely be "data the platform does not currently
have." The stronger boundary is a **transient exception event** whose value appears
only during a short open decision window.

## Why exception events are different

Examples observed in this scan:
- unexpected equipment breakdown;
- urgent inserted order;
- suddenly insufficient internal production capacity;
- instrument failure;
- reservation saturation;
- supplier/part shortage.

These events create:

```text
NORMAL ROUTE WORKED YESTERDAY
→ PRIVATE EXCEPTION OCCURS NOW
→ LOSS CLOCK STARTS
→ NORMAL INTERNAL PLAN NO LONGER WORKS
→ EXTERNAL SUBSTITUTE BECOMES DISPROPORTIONATELY VALUABLE
```

A stable marketplace can know that substitutes exist.

It may still not know **which user's normal route just failed right now**.

That timing asymmetry is more promising than private context alone.

## Next search direction

Run `ATTRACTION_SCAN_012` with working label:

`PRIVATE EXCEPTION EVENT × OPEN FAILOVER RAIL`

Search broad current reality for cases where:
1. a normal route is already in use;
2. a private, machine-observable exception abruptly makes that route inadequate;
3. delay creates a rapidly increasing and legible loss;
4. the decision window is short but still open;
5. a standardized substitute resource/action exists outside the current system;
6. external availability and action are machine-callable under stable rules;
7. neither incumbent side already owns both the exception signal and failover rail;
8. the switch is machine-resolvable without recurring expert interpretation;
9. the operator can be paid as a reusable machine routing function;
10. repeated exceptions improve routing coverage and outcome evidence.

Retain zero again if:
- the fallback requires human negotiation/approval;
- the substitute is not standardized enough to match automatically;
- an incumbent already owns event detection and failover;
- the route needs enterprise-by-enterprise consulting or recurring sales/delivery.
