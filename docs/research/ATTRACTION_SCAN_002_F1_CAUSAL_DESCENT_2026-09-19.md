## Executive truth

The formation survives at the level of **real-world tension** but not at the level of a distinct commercial control plane.

The underlying reality is strong:

- some residential private chargers sit idle for long periods;
- nearby EV owners can lack fixed installable spaces or reliable community charging;
- property/community actors control access, parking order, common-area coordination and safety;
- private-charger sharing is technically mature and already implemented by established charging operators.

The hypothesized residual was:

> property/community permission itself might be a standardized, routable unit that a new operator can aggregate.

After causal descent, that edge is **not proven**.

Current evidence instead indicates that the remaining hard work is a bundle of local control rights and project conditions:

```
PARKING RIGHT
+ PROPERTY RULE
+ VEHICLE ENTRY
+ COMMON-AREA GOVERNANCE
+ ELECTRICAL CAPACITY
+ CHARGER COMPATIBILITY
+ SAFETY / LIABILITY
+ REVENUE / PUBLIC-INCOME RULES
+ LOCAL INSTALLATION / OPERATIONS
```

Those controls do not collapse into one reusable permission object in the evidence reviewed.

Therefore:

```
IDLE ASSET = EVIDENCED
NEARBY DEMAND = EVIDENCED
TECHNICAL SHARING STACK = MATURE
PROPERTY SUPPORT BOTTLENECK = EVIDENCED
STANDARDIZED PERMISSION UNIT = NOT PROVEN
FOUNDER-INDEPENDENT ACTIVATION = NOT PROVEN
F1 = DEMOTED
COMMERCIAL CANDIDATE = NO
```

## 1. Actor and control-right map

### Charger / parking-space holder

Controls:
- personal charger availability;
- private-use priority;
- where allowed, sharing time and price.

Does **not** necessarily control:
- external vehicle entry;
- common road / gate usage;
- electrical capacity;
- community operating rules;
- public/common property;
- fire/safety rules.

### Nearby EV driver

Controls:
- demand timing;
- willingness to reserve/pay;
- compliance with parking/charging rules.

Does not control access rights.

### Property / community / parking manager

Controls or materially influences:
- gate access;
- parking order;
- common-area use;
- visitor management;
- operating rules;
- property-side settlement/fees;
- incident handling.

### Power / infrastructure layer

Constrains:
- available capacity;
- load;
- installation / upgrade feasibility;
- safe operation.

### Platform / charging operator

Can already provide:
- discovery;
- reservation;
- charger authorization;
- remote start/stop;
- billing;
- settlement;
- equipment monitoring;
- in some stacks, gate and smart-lock integration.

Therefore the platform is **not** the missing actor.

## 3. Why permission remains hard

### 3.1 Property support is situational

Current platform documentation explicitly says whether property consent is needed depends on:
- parking-space attributes;
- community management;
- vehicle access;
- construction/installation;
- on-site operation.

Source:
- https://docs.huibochong.com/private-charger-sharing/sharing-business-model/

That wording is structurally important: the permission rule is contextual, not a universal API.

### 3.2 Self-use installation rights do not automatically create sharing rights

A 2026 judicial case supports a resident's right, under the facts of that case, to install a charger on a fixed-use parking space and limits unreasonable refusal by property management.

But private sharing can add:
- third-party vehicle entry;
- recurring commercial use;
- parking turnover;
- service-fee / settlement questions;
- different load profile;
- incident/liability exposure.

Therefore the legal right to install for self-use is not equivalent to a standardized right to open a private charger as a shared community service.

Source:
- https://legalinfo.moj.gov.cn/zxxfyasf/202607/t20260720_537627.html

### 3.3 Shared/common-property economics are regulated and locally variable

Current property-industry analysis shows local rules increasingly constrain how common-property revenue and management fees are allocated.

Source:
- https://www.fangchan.com/data/369/2026-06-11/7475101501619507940.html

A 2026 local-government response for a community charging project also shows:
- platform service fees;
- electricity and maintenance costs;
- project losses in that instance;
- later distribution tied to owners' governance and contractual allocation.

Source:
- https://apps.ganzhou.gov.cn/xsqwlwzweb/szfbmwz/getContent?id=6bcc604d4f8ca6ac937420e9816e

This is not directly a private-sharing unit-economics sample, but it is evidence that community charging economics and governance cannot be assumed trivial.

## 4. Causal descent

### Surface symptom

“Private chargers are idle while nearby drivers need charging, but sharing is difficult.”

### C1 — users cannot discover or pay for private chargers

Result: `RESOLVED BY INCUMBENTS`.

Mature platforms already perform discovery, pricing, payment and sharing.

### C2 — chargers cannot technically be remotely shared

Result: `LARGELY RESOLVED`.

Current software/hardware stacks support remote control, authorization, metering, locks and settlement.

### C3 — gate / lock / settlement integration is missing

Result: `NOT A DISTINCT GAP`.

Current systems explicitly integrate gates, locks and multi-party settlement.

### C4 — property/community permission is missing

Result: `TRUE AS FRICTION, NOT PROVEN AS STANDARDIZED UNIT`.

The “permission” is really a composite of local rights, rules, capacity, safety, access and economics.

### C5 — a property group could aggregate that permission across many communities

Result: `PLAUSIBLE BUT NOT EVIDENCED`.

This would be the one route that could save the formation:
- one commercial relationship;
- repeatable deployment across many properties;
- standardized local implementation;
- concentrated demand acquisition.

But the current evidence set does not establish an active unmet buyer-side pull from property groups for a new neutral permission orchestrator. Existing charging operators already have reason to pursue those partnerships.

Under fail-closed rules:

`PLAUSIBLE != PASS`.

### C6 — a new operator can sit between property and charging platforms

Result: `NOT PROVEN`.

Without a unique control right, exclusive distribution channel, standardized compliance primitive or proprietary demand pool, this position risks becoming:
- business development;
- implementation coordination;
- local hardware project management;
- dispute/exception handling.

That is not the desired control-plane business.

## 5. Operator non-labor test

The current general formation requires too much recurring local work unless a concentrated permission owner is found.

Likely recurring tasks include:
- property acquisition;
- community-specific agreement;
- stakeholder communication;
- site survey;
- electrical / parking compatibility;
- installation coordination;
- access-system integration;
- exception handling;
- local maintenance.

Existing technical stacks reduce software labor but do not remove this local activation burden.

Result:

`FAIL FOR CURRENT GENERAL FORM`.

## 6. Self-propulsion test

A property-group rollout could in theory create compounding deployment economics.

But no current evidence proves that:
- one approval automatically unlocks many communities;
- property rules are portable;
- local infrastructure is sufficiently homogeneous;
- deployment cost falls fast enough;
- operator acquisition becomes inbound/self-reinforcing.

Result:

`UNPROVEN / TOO DEPENDENT ON HYPOTHETICAL GROUP-LEVEL CHANNEL`.

## 7. Economic attraction

Private-pile sharing can create owner income, and current products actively market that benefit.

However, platform economics appear competitive and potentially thin:
- some sharing platforms advertise very low technology service percentages;
- large charging operators already possess installed-user bases and charging demand;
- property/common-area revenue rules can constrain arbitrary platform extraction;
- physical activation and maintenance remain non-zero.

No evidence currently shows an unclaimed high-margin control point.

Result:

`OPERATOR ECONOMIC SURPLUS = NOT PROVEN`.

## 8. Structural learning that survives

The useful abstraction is not “private chargers.”

It is:

### PERMISSION DENSITY

A stranded resource is attractive only when the control rights needed to activate it are sufficiently concentrated.

```
HIGH RESOURCE IDLE RATE
+ HIGH DEMAND
+ DISPERSED PERMISSION
= MAY STILL BE A BAD ROUTING BUSINESS
```

A better opportunity has:

```
STRANDED VALUE
+ ACTIVE DEMAND
+ ONE / FEW AUTHORIZERS
+ STANDARD RULE
+ REPEATABLE SETTLEMENT
```

This becomes a research primitive:

`CONTROL-RIGHT CONCENTRATION / PERMISSION DENSITY`.

It is **not** a commercial candidate or watchlist item.
