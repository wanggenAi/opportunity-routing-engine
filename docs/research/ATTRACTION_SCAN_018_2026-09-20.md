## Direction 3 — freight promise/quote × realized cost/transit outcome

The hidden outcome is real:
quoted freight and planned transit can diverge from actual delay, cancellation,
accessorial charge and invoice.

But current freight intelligence already covers:
- real-time quote/booking;
- announced vs actual transit performance;
- cancellation/delay/congestion;
- invoice/accessorial auditing.

Verdict:
`DEMOTED / INDEPENDENT_PERFORMANCE_AND_AUDIT_DATA_LAYER_ALREADY_MATURE`.

## Direction 6 — empty-container return deadline × depot/appointment state

The loss window is genuine: missed free time creates detention/demurrage and depot
acceptance can be time-sensitive.

However the control surface is increasingly integrated:
- multi-carrier container tracking already exposes pickup/return nodes and overuse alerts;
- major port regions provide unified pickup/return appointment and payment systems;
- carrier products allow users to buy extra free time when delay risk appears.

Verdict:
`DEMOTED / REAL_EXCEPTION_BUT_TMS_PORT_CARRIER_LAYERS_ARE_INTERNALIZING_IT`.

## Direction 7 — cold-chain temperature exception × emergency storage/vehicle capacity

This is a true cross-domain emergency event:
temperature excursion can require immediate unloading, alternate refrigerated storage
or a replacement reefer vehicle.

But current cold-chain platforms already integrate IoT temperature alerts, WMS/TMS,
real-time capacity and automatic emergency actions such as nearby unloading or vehicle
replacement.

Verdict:
`DEMOTED / EXCEPTION_ACTION_IS_ALREADY_ENTERING_COLD_CHAIN_CONTROL_PLANE`.

## Direction 8 — weather/harvest shock × grain-drying capacity

This has strong participant attraction. A weather-driven harvest window plus local
drying-capacity shortage can create direct spoilage risk.

institutionalized:
- the national agricultural social-service platform aggregates service demand,

- local digital agricultural-service platforms offer booking and dispatch;
- drying is explicitly part of the service catalog and emergency agricultural-service
  system.

Verdict:
`DEMOTED / HIGH_ATTRACTION_BUT_OFFICIAL_SOCIAL_SERVICE_PLATFORM_OWNS_MATCHING_SURFACE`.

## Cross-scan learning

The key failure mode is stronger than Scan 017's "platform already exists":

```text
TRANSIENT EXCEPTION
+
HIGH IMMEDIATE LOSS
+
TWO DIFFERENT OPERATIONAL DOMAINS
DOES NOT YET CREATE A ROUTER
```

because mature industries tend to respond in one of two ways:

```text
A. DIGITIZED EXCEPTION
   → TMS / WMS / CLOUD / MARKET / OPERATOR CONTROL PLANE ABSORBS THE JOIN

B. UNDER-DIGITIZED EXCEPTION
   → THE ACTION STILL REQUIRES PHONE CALLS, EXPERT JUDGMENT OR BESPOKE COORDINATION
```

The attractive residual must sit between these failure modes.

## Scan-019 boundary

Do not search merely for another emergency.

Prefer a structure where:
1. the high-intent event is externally observable without prior enterprise integration;
2. multiple independent paid execution rails are already callable;
3. no one rail can naturally observe the decisive cross-rail outcome;
4. selection depends on transaction-generated outcomes, not public static parameters;
5. the operator can earn from completed machine-routed value rather than consulting;
6. a general Agent cannot reproduce the edge from ordinary context and public docs.

Compact form:

```text
SELF-REVEALING HIGH-INTENT EVENT
+
MULTIPLE PAID CALLABLE RAILS
+
POST-EXECUTION OUTCOME UNCERTAINTY
+
NO SINGLE RAIL OWNS CROSS-RAIL HISTORY
+
NATIVE OR TRANSACTION-LINKED OPERATOR ECONOMICS
→ POSSIBLE ROUTING ASSET
```

This retains the useful mechanism learned from Scan 015 without inheriting the
used-device vertical.
