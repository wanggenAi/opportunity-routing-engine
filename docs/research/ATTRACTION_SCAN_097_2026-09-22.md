## Boundary

After two China participant-authored passes repeatedly closed at physical, regulated, public or already-platformized control surfaces, Scan 097 changes only the evidence priority:

```text
CURRENT PARTICIPANT-RECORDED FRICTION
+ INDEPENDENT OBJECTIVE CORROBORATION
+ DECISIVE ACTIONS MOSTLY INSIDE PARTICIPANT-AUTHORIZED DIGITAL SYSTEMS
→ THEN INCUMBENT / MARGIN / GENERIC-AGENT PREFLIGHT
```

This is not a product category. It is a control-rights and machine-executability entrance filter.

## Result

| Formation | Why it fits the new entrance | Why it still fails promotion |
|---|---|---|
| Digital-invoice reimbursement preparation | User controls invoice files, browser/tax-verification interactions and packet preparation | Routine document work is generic-agent substitutable; enterprise expense platforms already own the paying workflow |
| Multi-platform creator publishing | Creator owns source content and authenticated accounts; upload is a digital action | Many active free/open-source and commercial tools already automate the exact logged-in-browser flow |
| Android multi-store release | Developer owns APK, metadata and store credentials; repeat release is digitally executable | DCloud and apkgo already automate multi-store submission; final store review/compliance remains external |

## F1 — Digital-invoice reimbursement preparation

A current 2026 participant describes manual tax-verification screenshots, cropping, renaming, XML retrieval, duplicate checking and file organization before reimbursement. This is exactly the kind of participant-controlled digital action Scan 097 was designed to surface. citeturn837887search12

The objective infrastructure is also ready: China's electronic-voucher accounting data standard explicitly supports XML digital invoices and is intended to connect reimbursement, accounting and archiving; tax authorities support PDF/OFD/XML retention. citeturn174525search5turn174525search1

But the commercial edge collapses under incumbent/substitution preflight. Current enterprise products already automate invoice collection, validation, reimbursement, accounting and compliant archiving. citeturn177984search2turn177984search10

**Verdict:** demoted.

## F2 — Multi-platform creator publishing

Current Chinese creators/developers document the repeated digital last mile directly. One 2026 project reports actual operation across six platforms and 300 videos; another describes content creation as automated while final platform publication remained the broken step until browser-account actions were wrapped for agents. citeturn837887search5turn837887search6

This formation has unusually good action-rights fit: the creator owns the content and already-authenticated platform sessions. But exact substitutes are abundant. Current open-source projects reuse local login state, publish to major Chinese platforms, adapt metadata and verify success. citeturn598319search2turn598319search1turn598319search0

**Verdict:** demoted. This is a highly automatable workflow, but it is already a crowded, low-barrier automation category and generic browser agents can reproduce the core operation.

## F3 — Android multi-store release

A current Chinese developer asks whether an Android app still must be pushed through Xiaomi, OPPO, vivo and Tencent one account/process at a time and whether a one-click publishing layer exists. Another current developer thread describes the fragmented qualification and distribution burden. citeturn334951search0turn879348search1

The action-rights fit is strong once accounts exist: the developer owns the APK, metadata and store credentials. DCloud's current docs show that multi-store upload is already available for several stores, while some stores still require manual first creation/release. citeturn334951search1

More decisively, apkgo is active in 2026 and already provides one-command multi-store upload, CI/CD integration, machine-readable output and a hosted commercial path. citeturn520576search0turn520576search1

**Verdict:** demoted.

## Learning

Scan 097 validates the new entrance but also reveals its main trap:

> participant-owned digital credentials + repetitive digital actions often describe the exact workload that browser agents, document agents and small open-source tools can commoditize fastest.

The answer is not to invent a more specific product after one pass. Scan 098 should repeat the same digital-action-rights-first method on a fresh formation-diverse China sample, with exact open-source substitutes included in the incumbent preflight.
