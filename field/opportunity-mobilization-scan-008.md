## Why the old closure is only partially reversed

Scan 007 correctly closed generic reverse engineering because mature national providers already offer:

- 3D scanning;
- reverse CAD;
- old-part replication;
- machining/printing handoff.

A new 2026-09-08 **徐州日报** report changes only the local/on-site part of that judgment.

徐州多帮三维科技 reports that before launch its team spent more than a month visiting nearly ten local manufacturing enterprises.

The reported finding was direct:

> Xuzhou manufacturers had reverse-engineering demand but struggled to find local providers.

The same company now reports actual projects including:

- deformation-repair scanning/modeling for large-tonnage engineering machinery;
- scanning/modeling and 3D-print trials for Mercedes-AMG body parts;
- a 17-meter large-component project.

Source:

- https://szb.cnxz.com.cn/xzrb/pad/con/202609/08/content_56400.html

This is materially stronger than vendor SEO.

It is current local evidence of:

```text
REAL PHYSICAL TASK
+
LOCAL DEMAND
+
HISTORICAL LOCAL PROVIDER SCARCITY
```

Therefore the narrow residual deserves recheck.

## What is *not* reopened

Do not reopen:

- generic reverse engineering;
- generic 3D scanning marketplace;
- generic no-drawing replacement-part sourcing;

The only eligible question is:

> For occasional Xuzhou industrial users with large, immovable, damaged or no-drawing parts, is there still a low-friction **on-site** task-routing residual after current local providers are considered?

# Rooter Execution Map

## Actor A

Occasional-use manufacturer or equipment owner.

## Actor B

Field-scanning node + replaceable reverse-modeling capability.

## Task definition

At minimum:

- object and site;
- size/material/surface;
- access constraints;
- required accuracy;
- required coverage;
- output format;
- intended use: repair / manufacture / fit / documentation;
- confidentiality/IP boundary.

## Executor

Qualified field-scanning provider and/or remote reverse-modeling engineer.

Rooter does not scan or model.

## Acceptance

Pre-agreed:

- scan accuracy;
- coverage;
- point-cloud completeness;
- STEP / IGES / CAD output;
- geometry/fit checks where required.

## Payer

Manufacturer/equipment owner.

## Money flow

```text
buyer
→ orchestration layer
→ field scan / modeling node
```

## Rooter role

- normalize task intake;
- route local field capacity;
- split capture from modeling when useful;
- define acceptance;
- QA;
- settlement;
- retain provider accuracy/response history.

## Rooter must not

- personally scan;
- personally build every CAD model;
- become a technical consultancy;
- cold-visit factories indefinitely to create demand.

# The hardest counterevidence: self-propulsion

The same **徐州日报** report that proves demand also directly damages the platform thesis.

徐州多帮三维科技 says it first tried online technical-service platforms aggressively.

After roughly six months:

- revenue was only about **RMB 7,000**;
- proceeds were largely consumed by customer acquisition;
- the founder concluded the online model did not fit the current stage.

The company then shifted toward:

- local industrial-park connections;
- targeted visits;
- short-video/social content.

This is crucial.

It means:

```text
REAL SERVICE BUSINESS
!=
SELF-PROPELLED ROUTING BUSINESS
```

If each project must be created by targeted factory visits, Rooter simply becomes the sales layer.

That fails the current thesis.
