# Opportunity Mobilization Scan 015 — repeated transaction failure still does not prove an open route

Date: 2026-09-19

## Result

Scan 015 deliberately started from stronger evidence than trends or generic pain:

> a transaction already exists, the incumbent route has already been used, and the actor visibly retries because the outcome failed.

That still produced:

# `RETAINED_CANDIDATES = 0`

The new rule is:

# `FAILED / RETRIED TRANSACTION != OPEN ROUTING GAP`

The failure cause itself must map to a narrow post-incumbent edge that Rooter can own without becoming the expert, prime contractor, qualification shell or maintenance manager.

---

## 1. Repeated VFD failure after warranty repair — real pain, mature RCA route

A current Xuzhou heavy-vehicle manufacturing procurement provides unusually direct evidence.

The dust-system VFD:

- had already failed twice;
- had a badly burned circuit board;
- was repaired by the warranty/manufacturer route;
- had normal line/motor insulation;
- still had no identified root cause for the repeated board burning.

The buyer is now explicitly purchasing:

- on-site root-cause diagnosis;
- corrective measures;
- a six-month commitment that the same fault will not recur.

Source:

- https://m.yfbzb.com/inviteBid/detail/20260706_611352747.html

This is a genuine post-incumbent outcome failure.

But it does not leave an empty expert market.

Current domestic providers already sell:

- 24×365 remote diagnosis;
- on-site diagnosis for complex faults;
- root-cause reports;
- repair verification;
- predictive maintenance;
- maintenance-management / equipment-hospital workflows.

Sources:

- https://www.zept.cn/zdfw.html
- https://www.izzty.com/service/iot/
- https://www.sbtyy.com/

The buyer also already has a functioning procurement route for the new outcome-level service.

So the missing layer is not:

> nobody can route this task.

A Rooter inserted here would most likely become:

- expert broker;
- maintenance coordinator;
- responsibility manager.

After one competent RCA provider is found, bypass risk is high.

Judgment:

`CLOSED_MATURE_RCA_DIAGNOSTIC_ROUTE`

## 2. Annual maintenance but recurring machining-center electrical faults — same conclusion

Another current Xuzhou procurement describes four machining centers:

- roughly seven years old;
- already covered by annual outsourced maintenance;
- still suffering repeated electrical faults;
- with welding smoke and metal dust entering cabinets because no physical isolation exists.

Regular cleaning has not eliminated the failure pattern.

The buyer is again outsourcing a targeted electrical-maintenance package.

Source:

- https://www.yfbzb.com/inviteBid/detail/20260912_630541771.html

This is real repeated loss.

But the failure now points toward:

- environmental isolation;
- condition monitoring;
- fault diagnosis;
- engineering correction;
- maintenance-scope redesign.

Those are already sold by current diagnostic/predictive-maintenance providers.

So:

```text
OLD MAINTENANCE CONTRACT FAILED
!=
NO MARKET FOR BETTER DIAGNOSIS
```

Judgment:

`CLOSED_DIAGNOSTIC_MAINTENANCE_ROUTE`

Scan 015 also searched repeated procurement attempts.

Examples include:

- a small Xuzhou telecom equipment-repair DICT project republished a second time;

- military/equipment projects reaching third rounds.

Sources:

But visible reasons frequently include:

- insufficient valid responders;
- only one bidder passing initial review;
- qualification thresholds;
- required safety/industry certificates;
- minimum-valid-bidder rules.

Current procurement rules themselves define what happens when valid responses remain below the threshold, including re-tendering and later direct-purchase paths.

Example:

- https://www.yfbzb.com/inviteBid/detail/20260908_629102445.html

Therefore:

```text
THIRD TENDER
!=
MARKET HAS NO SUPPLY
```

A Rooter attempting to “fix” this would drift into:

- tender agency;
- prime contracting;
- qualification-shell behavior;
- compliance intermediation.

That is not the desired low-permission control plane.

Judgment:

`CLOSED_HIGH_PERMISSION_PROCUREMENT_RULE_ROUTE`

## 4. Xuzhou cross-city testing — target not bound

A key target from prior doctrine was:

> one Xuzhou enterprise still forced to send one specific test to Nanjing/Suzhou/Shanghai, paying measurable time/cost, after current shared-testing routes are considered.

Scan 015 did not bind that case.

Current evidence instead shows that cross-city delegation itself is already routable.

- Nanjing;
- Suzhou;
- Qingdao;

Source:

- https://njsj.nanjing.gov.cn/njszwfwglbgs/202606/t20260617_5861941.html

Current Xuzhou-area inquiries explicitly ask suppliers to state:

- material lead time;
- whole repair period;
- whether production must stop;
- if so, for how long.

Examples include:

- blasting-elevator top roller shaft wear;
- transformer GIS chamber low pressure;
- industrial robot repair.

Sources:

- https://www.yfbzb.com/inviteBid/detail/20260918_632537679.html
- https://www.yfbzb.com/inviteBid/detail/20260918_632537775.html
- https://yfbzb.com/inviteBid/detail/20260918_632567979.html

This is valuable evidence that:

```text
TIME-TO-RESTORATION
```

is a real economic variable.

But those tasks already enter direct repair/procurement channels.

Urgency alone does not expose a new missing edge.

Judgment:

`PATTERN_SENSOR_ONLY`

# Cross-industry learning

Scan 015 strengthens another hard rule:

```text
INCUMBENT USED
+
OUTCOME FAILED
+
ACTOR RETRIES
!=
ROOTER GAP
```

Ask why the incumbent route failed.

Possible answers include:

- wrong technical scope;
- qualification rules;
- minimum-bidder rules;
- buyer governance;
- need for a more specialized provider;
- normal cross-city outsourcing.

Only some failure causes could support a new control plane.

None of the strongest current examples produced a low-permission, non-bypassable Rooter edge.
