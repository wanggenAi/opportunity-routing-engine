> buyer has a real functional requirement, compatible supply exists, and procurement channels exist — but model numbers, standards, interfaces or performance envelopes do not line up cleanly.

Result:

# `RETAINED_CANDIDATES = 0`

## 1. Bearings — closed

Bearing substitution can be expensive when the wrong candidate fits dimensionally but fails under:

- load;
- speed;
- lubrication;
- temperature;
- contamination;
- mounting;
- life requirements.

But the market already provides:

- cross-brand model databases;
- standard/form-factor mapping;
- manufacturer cross-reference tools;
- distributor/application-engineer confirmation.

Current cross-reference resources directly map third-party models to replacement families.

For the hard cases, the supplier/distributor already asks for operating context and owns selection advice.

No named Xuzhou/Jiangsu buyer was bound to a repeated measurable loss **after** those routes were considered.

Judgment:

`CLOSED_TOOL_PLUS_APPLICATION_ENGINEERING_ROUTE`

Sources:

- https://www.caloc.cn/replace
- https://www.nsk.com/tools-resources/bearing-cross-reference/

## 2. Discontinued PLC / HMI / drive replacement — closed

This was the strongest candidate for a substitution residual.

The difficulty is real:

```text
OLD DEVICE DISCONTINUED
→ NEW HARDWARE EXISTS
→ BUT
MECHANICS / WIRING / PARAMETERS / BUS / PLC PROGRAM
MAY CHANGE
```

That is exactly where a naive catalog replacement can fail.

But OEMs already own this handoff.

Current routes include:

- Siemens replacement tables;
- Keyence discontinued-model replacement lists;
- Schneider migration guidance;
- Siemens retrofit configurators;
- conversion of old drive parameters into replacement-device parameters;
- engineered retrofit kits;
- ABB modernization/retrofit;
- third-party PLC/drive/servo upgrade and commissioning.

So the hard residual is not:

> nobody knows how to connect old to new.

It is:

> engineering work is required.

And that work is already a product.

Judgment:

`CLOSED_OEM_INTEGRATOR_MIGRATION_ROUTE`

If Rooter must repeatedly inspect electrical drawings, choose parameters, edit PLC code and commission equipment, Rooter has become the controls engineer.

That violates operator exit.

## 3. Hydraulic / seals / interfaces — closed

Hydraulic and sealing substitutions look fragmented because manufacturers use many catalog systems.

But current structure already includes:

- GB/ISO-derived interface standards;
- selectors by size/material/hardness/standard;
- cross-reference data;
- specialist distributor technical confirmation.

For commodity-compatible substitutions, the problem is structured enough for catalogs.

For uncertain chemical/pressure/application cases, the distributor/application engineer already owns the judgment.

No named post-incumbent residual was bound.

Judgment:

`CLOSED_STANDARD_PLUS_DISTRIBUTOR_ENGINEERING_ROUTE`

---

## 4. Filters — closed

Wrong replacement filters can create real loss through:

- incompatible dimensions;
- wrong micron rating;
- unsuitable media;
- pressure/flow mismatch.

But current suppliers already publish broad OEM replacement portfolios and application guidance.

This is a classic cross-reference function.

Judgment:

`CLOSED_CROSS_REFERENCE_ROUTE`

Sources:

- https://www.donaldson.com/
- https://shop.donaldson.com/

## 5. Industrial lubricants — closed

Cross-brand lubricant replacement is not only about viscosity.

The real decision can involve:

- OEM approvals;
- additives;
- elastomer/material compatibility;
- operating temperature/load;
- drain interval.

Yet major suppliers already provide equipment-specific recommendation and cross-brand replacement advice.

The hard cases are handled by technical service.

Judgment:

`CLOSED_OEM_RECOMMENDATION_ROUTE`

Source:

- https://www.shell.com.cn/

# Cross-industry structure

The pattern is now clear:

## Easy case

```text
OLD / OTHER BRAND MODEL
→ CROSS-REFERENCE DATABASE
→ CANDIDATE REPLACEMENT
```

This is data/search infrastructure.

## Hard case

```text
CANDIDATE REPLACEMENT
+
APPLICATION CONTEXT
+
WIRING / PARAMETERS / PROGRAM / PROCESS
→
APPLICATION ENGINEER / OEM / INTEGRATOR
```

This is an engineering service.

The apparent “middle gap” disappears.

---

# Rooter fit

A Rooter opportunity would require:

```text
BUYER NEEDS SUBSTITUTE
+
SUPPLY EXISTS
+
CURRENT CROSS-REFERENCE / OEM / DISTRIBUTOR FAILS
+
TASK CAN STILL BE STANDARDIZED
+
OBJECTIVE ACCEPTANCE
+
ROOTER DOES NOT BECOME ENGINEER
```

No such repeated named Xuzhou/Jiangsu residual was bound.

The likely operator role in hard cases would instead become:

- collect application conditions;
- interpret drawings;
- choose equivalent product;
- own compatibility risk;
- configure parameters;
- coordinate installation;
- troubleshoot commissioning.

That is not the intended control plane.

# Next search zone

Fresh Scan 013 should stop generic substitution research.

A narrower possible failure is **between already-existing services**:

```text
SERVICE / PROVIDER A COMPLETES ITS PART
↓
SERVICE / PROVIDER B SHOULD CONTINUE
↓
TRANSACTION STALLS OR COST BLOWS UP
BECAUSE:
  RESPONSIBILITY IS UNCLEAR
  REQUIRED EVIDENCE IS NOT HANDED OVER
  SCHEDULING / ACCESS DOES NOT LINE UP
  ACCEPTANCE OWNERSHIP FALLS BETWEEN PARTIES
```

This is not permission to invent a “project-management platform.”

Retain only when public evidence shows:

1. one named recent transaction;
2. both adjacent services already exist;
3. the handoff failure repeatedly creates measurable cost;
4. neither existing actor already owns the handoff;
5. the handoff can be standardized and objectively accepted;
6. Rooter can exit execution and sales.

Do not commit Scan 013 merely because multi-party projects are complex.
